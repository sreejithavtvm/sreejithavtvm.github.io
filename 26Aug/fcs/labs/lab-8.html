Implementation plan

Build it in two stages

Unit-test program flow before adding stack frames and function calls.

Stage I

Program flow

Implement the VM branching commands:

  • label labelName
  • goto labelName
  • if-goto labelName

Ensure labels are scoped so that identically named labels in different functions do not collide.

Stage II

Functions and bootstrap

Implement:

  • function functionName nVars
  • call functionName nArgs
  • return
  • Translation of all .vm files in one directory
  • Bootstrap code that sets SP=256 and calls Sys.init

Function-call state

What the generated assembly must preserve

A function call must be able to return to the caller with its memory-segment view restored.

On call

Create the callee's frame

  • Push a unique return address.
  • Save the caller's LCL, ARG, THIS, and THAT.
  • Reposition ARG for the callee's arguments.
  • Set LCL=SP and jump to the called function.
On return

Restore the caller's frame

  • Recover the return address from the current frame.
  • Move the return value to argument 0.
  • Restore SP immediately above the return value.
  • Restore THAT, THIS, ARG, and LCL, then jump to the return address.

Initialization

Know when bootstrap code is expected

The tests deliberately introduce bootstrap responsibilities gradually.

First three
BasicLoop, FibonacciSeries, and SimpleFunction use test scripts that manually provide the initialization they need.
Last two
FibonacciElement and StaticsTest expect your generated program to contain bootstrap code.
Bootstrap
Set SP to 256 and generate the equivalent of call Sys.init 0.

Testing and debugging

Test every stage before continuing

Use the VM emulator to understand behavior and the CPU emulator to test generated assembly.

For each test program

  1. Run the program in the VM emulator with XxxVME.tst to understand its intended behavior.
  2. Translate the required .vm file—or the complete directory for a multi-file program—into one .asm file.
  3. Inspect the generated assembly for syntax, label-scope, stack-frame, and control-flow errors.
  4. Run the assembly on the CPU emulator using Xxx.tst.
  5. Compare the result with Xxx.cmp. Correct the translator and regenerate the assembly if the test fails.

Implement in the supplied order. Later programs depend on earlier features, so skipping directly to recursion or multi-file translation makes failures much harder to diagnose.
