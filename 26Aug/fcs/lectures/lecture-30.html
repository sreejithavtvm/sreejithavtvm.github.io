Start with the simplest statement: how would we parse return?

Exercise 2

How Would You Implement compileReturn()?

returnStatement: 'return' expression? ';'

Write the routine for both return; and return x;. Reveal the code after students have tried.

compileReturn():
    openTag('returnStatement')
    expectAndWrite('return')
    if currentToken != ';':
        compileExpression()
    expectAndWrite(';')
    closeTag('returnStatement')

Convention: expectAndWrite(t) checks, writes the XML leaf, and advances; expectIdentifierAndWrite() does the same for an identifier. Treat compileExpression() as a helper for now—we will design it later in this lecture. Small helpers need not create an enclosing XML tag.

Next: a do statement contains a subroutine call.

Exercise 3

How Would You Implement compileDo()?

doStatement: 'do' subroutineCall ';'

Try do Output.printInt(x);. Which routine should recognize the call between do and ;?

compileDo():
    openTag('doStatement')
    expectAndWrite('do')
    compileSubroutineCall()
    expectAndWrite(';')
    closeTag('doStatement')

compileSubroutineCall() is a helper we will design after expression lists. It writes tokens inside the doStatement, not an extra subroutineCall XML tag.

Next: an if statement has an optional else branch.

Exercise 4

How Would You Implement compileIf()?

ifStatement: 'if' '(' expression ')' '{' statements '}'
             ('else' '{' statements '}')?

Handle both an if without else and one with else.

compileIf():
    openTag('ifStatement')
    expectAndWrite('if'); expectAndWrite('(')
    compileExpression()
    expectAndWrite(')'); expectAndWrite('{')
    compileStatements()
    expectAndWrite('}')
    if currentToken == 'else':
        expectAndWrite('else'); expectAndWrite('{')
        compileStatements()
        expectAndWrite('}')
    closeTag('ifStatement')

Exercise 6

How Would You Implement compileLet()?

letStatement: 'let' varName ('[' expression ']')?
              '=' expression ';'

Cover both let x = 1; and let a[i] = x;.

compileLet():
    openTag('letStatement')
    expectAndWrite('let')
    expectIdentifierAndWrite()
    if currentToken == '[':
        expectAndWrite('[')
        compileExpression()
        expectAndWrite(']')
    expectAndWrite('=')
    compileExpression()
    expectAndWrite(';')
    closeTag('letStatement')

These routines call compileExpression(). What does an expression contain?

Expressions

Read the Complete Expression Rules

An expression begins with a term, then may continue with operator–term pairs. A term can itself contain another expression.

The symbol * appears twice here, with two different meanings.

Expressions

Two Meanings of *

Grammar notation: repeat
expression: term (op term)*

The unquoted * says “zero or more operator–term pairs.” It is an instruction to the parser, not a Jack token.

Jack token: multiply
op: '+' | '-' | '*' | ...

The quoted '*' is a Jack operator token. For now, the parser writes <symbol> * </symbol>; it does not perform multiplication.

Parsing plan: recognize a term; while the next token is an operator, record that operator and recognize another term.

Let's trace a parenthesized expression containing multiplication.

Exercise 7

Parse 2 + (3 * 4)

Which parts belong to the outer expression, and which belong to the expression inside the parentheses?

let result = 2 + (3 * 4);

Outer expression: term 2, operator +, term (3 * 4).

Inside the parentheses: term 3, operator *, term 4.

The inner compileExpression() stops before ); the outer one stops before ;. Parentheses make the intended grouping explicit—Jack does not require them around every expression.

How can parser routines follow this nesting?

Expressions

Parse Terms, Then Operator–Term Pairs

compileExpression():
    compileTerm()
    while currentToken is an operator:
        compileOperator()   // write operator and advance
        compileTerm()

compileTerm():
    if currentToken == '(':
        writeAndAdvance('(')
        compileExpression()
        writeAndAdvance(')')
    else:
        handle the other term forms

A parenthesized expression is a term. The recursive call handles its contents; the surrounding call then continues with any following operator–term pairs. compileOperator() only records the operator—it does not calculate a value.

Calls can pass zero or more expressions. How do we parse that list?

Exercise 8

How Would You Implement compileExpressionList()?

expressionList: (expression (',' expression)*)?

It must accept both f() (empty list) and f(x, 2 + y). The caller has already read (.

compileExpressionList():
    openTag('expressionList')
    if currentToken != ')':
        compileExpression()
        while currentToken == ',':
            expectAndWrite(',')
            compileExpression()
    closeTag('expressionList')

The list leaves the closing ) for its caller. compileExpression() stops before a comma or closing parenthesis because neither is an operator.

Now use this list inside a subroutine call.

Exercise 9

How Would You Implement compileSubroutineCall()?

subroutineCall: subroutineName '(' expressionList ')' |
  (className | varName) '.' subroutineName '(' expressionList ')'

Cover move(x) and Math.multiply(x, 2).

compileSubroutineCall():
    expectIdentifierAndWrite()
    if currentToken == '.':
        expectAndWrite('.')
        expectIdentifierAndWrite()
    expectAndWrite('(')
    compileExpressionList()
    expectAndWrite(')')

This helper writes tokens inside the surrounding statement or term. The Project 10 XML has an expressionList tag, but no separate subroutineCall tag.
